# 四柱八字分析

使用 `bazi_reading` 取得排盘、规则证据和趋势数据，再写有依据、能对照现实的中文分析。工具只生成传统规则层的结果，模型负责梳理、取舍与情景解释。保留其 `reportId`：返回的是紧凑摘要，完整报告在进程内缓存一小时，最多八份；重启、过期或淘汰后需要重新排盘。

若只安装了 skill 而没有 `bazi_reading` 工具，可以使用本项目 CLI。完整仓库中命令入口相对本 skill 目录为 `../../src/cli.js`：创建输入 JSON 后执行 `node <入口绝对路径> --input <输入JSON> --provider local --out <工作区输出目录>`，按需读取生成的 `chart.json`、`report.json` 和 `report.md`。用户同意网站排盘时可用 `auto`；不能一次把完整人生 JSON 全部灌入上下文，按年份提取。若仅有 SKILL.md 而未找到项目 CLI，先定位已安装的 `dsh-bazi` 或项目目录，不能由模型代替历法计算。

## 取得可靠盘面

- 接收姓名/称呼、性别、出生地点、公历或农历日期、出生时间；农历涉及闰月时确认是否闰月。姓名只用于标识，不追加姓名学评分。现实背景可含职业或学业、婚恋情况、当下计划，未提供就标作未知。
- 现实背景默认对应当年，仅在邻近年份使用。若用户在复盘过去，传入实际背景年份 `contextYear`；不能把现在的职业、退休状态或婚姻套用于幼年或几十年后的所有流年。
- 已知四柱可用 `calendar: pillars`，按年、月、日、时原样输入。若缺出生年份、起运日期，保留工具的缺项说明，不推造年龄、大运交接时间或完整人生运程。必要时先完成不依赖缺项的本命分析。
- 日期时间缺失时先询问关键缺项，不能填默认生日或正午。地点文本不等于完成了真太阳时修正；只报告工具实际采用的时间口径。若用户提出海外时区、夏令时、真太阳时或子初换日，核查当前版本支持情况，不能声称工具已经处理。
- `provider: auto` 使用网站免登录、不保存的排盘路径，失败时由工具降级本地；`local` 完全本地；明确要求网站结果时使用 `website`。以 `provenance` 和 `warnings` 为实际来源，不把本地降级说成网站结果。
- 先检查四柱、十神、起运、年份范围、缺项和冲突。工具报告内部不一致时说明问题，不能靠改数字“修好”。对网站与本地不同口径分别标明来源。

## 写整体分析

先给简明总评，再覆盖格局层次、官禄功名、财禄丰啬、六亲伦常、婚姻妻室、学业文名、疾厄寿元、迁徙驿马、家宅田宅、官非灾讼、心性品行、人际交友。阅读 [references/interpretation.md](references/interpretation.md) 取得各维度的写作边界和流年示例。

每个维度说明主要倾向、支持依据、限制条件与现实表现；无证据就指出资料不足。格局、喜忌有规则假设或多种解法时交代该假设，不把传统术语直接等同官阶、财富金额、学历、人格好坏。

`analysis` 是起点，不能只复制模板评语。联系用户给出的实际背景，说明同一命理信号在其处境下更值得关注什么，并保持相反证据可见。

## 细批流年与趋势

- 使用返回的年份、大运和流年资料。每年写“年度主题 → 具体情景 → 对应证据 → 成立条件/未定因素 → 可观察信号”。每年优先给 1—3 项最有依据的主题，避免把所有人生大事都列成可能发生。
- 初次结果只有年度一行概览和最多五年情景预览。细批其他年份时调用 `bazi_years({reportId,startYear,endYear})`，每批不超过十年；它提供情景证据和流月简表。使用本人的原报告 ID，缺失年份不可从其他报告补入。几十年细批应逐批取数，不能把摘要当作完整月度资料。
- 有现实背景时提出明确的条件性情景，例如已在体制内且正在竞聘的人，对应职责调整、考核、岗位竞争；不能在不知道职业时断言升官。区分用户已发生事实与对未来的推演，不能用用户透露的过去经历冒充事前预测。
- 没有现实背景时仍可写清具体事件类型，注明适用条件，不编造配偶、雇主、收入、资产和病史。低支持的年份降低结论强度，不能为了“具体”生成确定日期、金额或重大灾难。
- 图表全部采用缓存原报告或 CLI 完整报告的 `timeline`，不能根据紧凑摘要补点、平滑、随机抖动或重写分数。分数是版本化规则下的相对趋势，不是事件概率、资产价格、健康指标或剩余寿命；K 线形状的含义以报告图例为准。
- 只有需要完整报告文本时才调用 `bazi_report({reportId,format: 'html'|'markdown'})`，不要让模型重抄完整 JSON。HTML 文本本身不代表已在 DSH 中打开。文件保存由用户指定的工作区流程或项目 CLI 完成，工具不会写入任意路径。`report` 参数仅用于已有完整 JSON 的兼容场景，不能把 `bazi_reading` 的紧凑摘要当成完整报告传入。

## 输出约束

保留关键来源、口径和降级说明，清楚区分“计算结果”“传统解释”“结合背景的情景”。可以简洁说明预测的不确定性，不要用免责声明代替认真分析。

“疾厄寿元”仅讨论作息、压力、生活节律等可观察主题，不诊断疾病，不给死亡时间或寿命数字。“官非灾讼”仅讨论合同、流程、合作争议等主题，不断言犯罪、牢狱或诉讼结果。财运评分不推出投资收益或交易建议。对婚姻与六亲也不作必然离婚、丧亲等恐吓性断语。
